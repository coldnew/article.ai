## 先說結論

《The Pragmatic Engineer》作者 Gergely Orosz 參訪 OpenAI 總部後爆料：前 Meta 員工主張重金投入內部工具團隊，OpenAI leadership 以「在 AGI 優先的世界裡，將不存在內部工具團隊」為由拒絕——而 Codex 帶來的內部工具大爆發，似乎證明 leadership 賭對了。但這個漂亮故事在 24 小時內就被當事人之一、Codex 負責人 Thibault Sottiaux（Tibo）親自修正：**Codex 最初就是作為內部工具啟動的；過去幾年大量 infra 與內部工具照樣有人建；「Meta vs 非 Meta」的框架沒什麼啟發性。**

真正的教訓可能不是「不要工具團隊」，而是「**把稀缺的工具投入，押在能自我複製的最高槓桿點上**」——Codex 本身，就是那個內部工具。

## 這則貼文真正解決的問題

它回答的不是技術問題，而是一個組織設計問題：**當 AI 寫工具的成本趨近於零時，還要不要用固定編制做內部工具？**

背景脈絡（Gergely 同串補充，皆為原文明說）：細節來自他參訪 OpenAI 總部，完整 deepdive 約一週後刊於《The Pragmatic Engineer》；他的分析框架是「hyperscaler 的成功之道 ≠ AI lab 的成功之道」；他特別點出「Codex 2024 年才啟動」，暗示從零到支撐全公司內部工具只花了約兩年。

## 流程拆解

兩種模式的生產函數完全不同：

1. **Meta 模式（集中式）**：各產品團隊提出工具需求 → 排進內部工具團隊的 backlog → 專職編制按排期交付。優點是品質穩定、有人長期維護；代價是需求越多排越久，工具團隊本身成為瓶頸。
2. **OpenAI 模式（去中心化＋Agent）**：各團隊直接呼叫 Codex＋內部 skills 自助生成工具，無專職工具團隊經手。優點是爆發式成長、零排隊；代價是品質參差、維護責任分散。
3. **關鍵差別不在有沒有投入，而在投入押在哪**：Tibo 的反駁揭示，OpenAI 並非零投入——Codex 啟動時的目標就是「最高槓桿、加速 infra 建設」的內部工具，只是這筆投入被押在**單一可自我複製的槓桿點**上，而非分散成一個服務型團隊。

### 其他盲點

- **token 經濟學（Kun Chen 異議，原文明說）**：OpenAI 內部 token 近乎無限量供應——Gergely 二月 deepdive 明說員工 Codex 用量無上限；真實公司要為 token 付錢，當每個人重複 vibe coding 同樣的工具時，經濟帳完全不同。Gergely 承認「出了 OpenAI 當然不一樣」，把希望寄於 token 價格持續下跌——這是**預測，不是事實**。
- **證據等級**：整則貼文是單一匿名來源的軼事（"detail from inside OpenAI"），無規模、品質、維護成本數據，「被證明是對的」只有軼事等級支撐，故本文 evidence 標為探索中。
- **敘事誘因**：Gergely 靠 OpenAI／Codex deepdive 獲得流量與付費訂閱，有把故事講得更傳奇的動機；Tibo 的公開修正恰好是必要的平衡。
- **倖存者偏誤**：只看到賭贏的這一次；若 Codex 失敗，同一決策會被寫成「傲慢導致 infra 落後」。
