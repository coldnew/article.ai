## 一句話結論

@GitHub_Daily 介紹騰訊開源的 TeamAI（`Tencent/teamai-cli`，3,244 星、今天還有推送）：團隊的 Skill、規則、Agent、Hook、MCP 全放進一個共享 git 倉庫，用 push→審核→pull 取代微信手傳配置——貼文裡的每個功能點我都回 README 逐一核過，全對得上。

## 這篇文章真正解決的問題

團隊裡幾個人都用 Claude Code、Codex，每人一套 Skill 和規則。同事調好一條規則，微信發過來手動粘進配置，過兩週他又改了，誰也不知道。這是所有「AI 原生團隊」都會撞上的腐爛問題：配置是散裝的，沒有版本、沒有審核、沒有同步。TeamAI 的答案是把團隊配置當代碼管——同一個倉庫、同一個合併請求流程。

## 流程拆解

README 把 TeamAI 切成三層，這個分層比貼文講得更清楚：

**第一層 Team Execution：讓每個 agent 照團隊的方式幹活。** `init`／`pull`／`push` 管 skills、rules、agents、hooks、MCP、env。成員一條命令初始化，之後每次開 AI 會話，SessionStart hook 自動 `teamai pull` 拉最新版。貼文說的「寫一份轉 11 家格式」對得上：相容矩陣剛好 11 行——Claude Code、Codex、Cursor、CodeBuddy、OpenCode，加上 DeepSeek Harness、Hermes、OpenClaw、Qoder、WorkBuddy、ZCode。

![散裝配置 vs 共享倉庫：push→審核→pull，會話自動同步，寫一份轉 11 家。](/article.ai/articles/tencent-teamai-github/figure-01-git-flow.svg)

<small class="figure-caption">圖 1｜本站自繪：微信手傳 vs git 流程對照，11 家相容名單來自 README 矩陣。</small>

**第二層 Team Context（beta）：讓每個 agent 懂團隊。** 兩個東西：recall（團隊知識回溯）與 learnings、codebase graph、`teamwiki`。貼文說的「問端口衝突前先查誰踩過」就是 recall：`teamai pull` 會部署內建的 `teamai-recall` subagent，動手前先抽關鍵詞、查團隊知識、回結構化摘要，不相關的任務會跳過檢索。`teamai import` 則把源碼倉庫解析成結構化圖谱（組件、介面、配置、跨倉庫 import 邊），給 recall 做圖增強重排。

**第三層 Team Improvement（beta）：讓每次執行都改善團隊。** 核心就是貼文說的「摩擦分」：會話結束時 Stop hook 打分，訊號很具體——你中途打斷或糾正過 AI、拒絕過工具調用、AI 反覆重試失敗工具。分夠高才提醒，用 `/teamai-share-learnings` 把踩坑總結成文件推回團隊倉庫。README 還補了一個貼文沒提的細節：順手但例行的長會話（很多工具調用、零摩擦）不會觸發，每個會話最多提醒一次。

![摩擦分迴圈：踩坑→沉澱→回查，附兩個但書。](/article.ai/articles/tencent-teamai-github/figure-02-friction-loop.svg)

<small class="figure-caption">圖 2｜本站自繪：摩擦分觸發沉澱、沉澱供給回查的迴圈；但書來自 README 原文。</small>

另外兩個管理功能：`teamai roles` 定義角色→命名空間映射，後端只同步後端那組 Skill；`teamai source` 可以訂閱別隊的公開倉庫，pull 時自動同步。一個人用也成立：當多台機器的配置同步工具。

## 風險與盲點

- 【原文明說＋推斷】知識回溯**預設關閉**，要 `teamai.yaml` 顯式打開。貼文寫「開了知識回溯後」是誠實的，但讀者若沒注意到這個前提，會以為開箱即用。
- 【原文明說】Context 與 Improvement 兩層都掛著 beta。只有 Execution（同步配置）是成熟功能，迴圈部分還在孵化。
- 【合理推斷】倉庫 2026-04-27 才建，3,244 星在騰訊開源矩陣裡不算大（对比同門動輒上萬星的項目）。星數＋今日仍有推送，證明活著，但不證明團隊流程已被大規模驗證。
- 【未被支撐】摩擦分的權重與閾值 README 沒公開，啟發式是否真能區分「值得沉澱的坑」vs「單純的爛會話」，目前只有機制描述、沒有數據。
- 【來源性質】貼文帳號是 8.4 萬追蹤的搬運型帳號（轉述＋導流），不是騰訊官方。本文所有功能宣稱已用 README 原文交叉核對，貼文本身只當「發現管道」，不當證據。
