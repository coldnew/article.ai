## 一句話結論

《南晚Nanwan X 貼文》對 ScaleMAS 的機制轉述基本靠譜（三操作、引用加權、128 agent 都有原文依據），但有兩處硬傷：作者機構是哈佛＋Meta FAIR＋Kempner，**沒有 MIT**；55.1%／80.0% 是 4 agent 設定下的數字，不是 128 agent 跑出來的。

## 真正解決的問題

《X 貼文》解決敘事問題：把「人多變笨」包裝成介質缺失的故事，用登月／Linux 類比讓結論好傳播。《論文》解決技術問題：把協調結構從 agent 指令裡抽出來放進共享介質，用 k 上界保證讀負擔有界、用引用次數當品質代理、用訊息持久化容忍掉線，附自建 Contradiction Audit 基準證明擴展性。

## 風險與盲點

1. **裁判也是 LLM**：Contradiction Audit 的矛盾注入與四輪 judge 全用 GPT-5.6，自己出題自己改卷；且文中模型（Qwen3.5-9B、Claude-5-Sonnet、GPT-5.6）皆為未來式，外人無法獨立復現。
2. **未見公開程式碼**：全文只提到 smolagents／mini-SWE-agent harness，無倉庫連結，工程細節以附錄為準。
3. **128 只覆蓋一半基準**：BrowseComp-Plus 與 SWE-bench 到 16 即止，128 的成績只在 FATE-M（趨平）與 Contradiction Audit（50.9%）上成立。
4. **作者為 HKU 在讀博士**，屬前沿追蹤型帳號，無商業漏斗，但「里程碑之作」屬個人評價，非同行共識。
