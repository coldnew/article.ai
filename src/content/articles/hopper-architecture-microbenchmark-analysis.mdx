## 一句話結論

《Dissecting the NVIDIA Hopper Architecture through Microbenchmarking and Multiple Level Analysis》這篇港科大廣州團隊的 Hopper 微基準論文，炒作成分集中在標題級數字的口徑不一：摘要寫 TMA 讓矩阵乘法加速 1.5 倍，但內文 GEMM 曲線在大矩阵下是 600 對 450 TFLOPS、約 1.33 倍，兩者對不上【從原文可直接推出】；成立的部分是硬的——wgmma 指令可達理論峰值九成五以上、FP8 實測為 FP16 的 1.99 倍、DSM 把跨 SM 通訊延遲壓到 6.13 分之一、DPX 在 16 位元整數微基準最高 13 倍且 Smith-Waterman 實走 4.75 倍，全部有表格與可重現的開源 artifact 撐腰，是一份調校指南等級的實測，而不是官方白皮書的複述。

## 這篇文章真正解決的問題

《Dissecting the NVIDIA Hopper Architecture》這篇論文解決的是技術問題，不是敘事問題：NVIDIA 維持約兩年一代的架構節奏，但公開的微架構規格始終稀缺，開發者拿著 Hopper 卻不知道新單元到底多快、什麼形狀下會失速【原文明說】。沒有這些數字，效能建模、模擬器與跨領域最佳化都只能靠猜。

它的方法是把五大單元——記憶體子系統、TMA、Tensor Core、DSM、DPX——各做指令層、函式庫層、應用層三層評估【原文明說】，並用三張卡橫向對照：A100 PCIe（Ampere）、RTX 4090（Ada Lovelace）、H800 PCIe（Hopper），前兩者是各自世代的代表卡【原文明說】。軟體環境是 RTX 4090 用 driver 530.30.02 配 CUDA 12.1，A100 與 H800 用 driver 560.35.03 配 CUDA 12.6【原文明說】。這組設計的價值在於：同一把尺量三代，Hopper 的新東西到底是架構紅利還是時脈紅利，一翻表就知道。

另外要先交代出處鏈：arXiv 頁面掛著管理員註記，指本稿與 arXiv:2402.13499 有大量文字重疊；論文首頁腳註自己寫明，這是基於並延伸自發表於 IPDPS 2024 的會議論文《Benchmarking and Dissecting the Nvidia Hopper GPU Architecture》，新增 L2 分區快取測試、wgmma 能耗、完整 DSM 評估、應用層 DPX 與非同步編程下的 TMA【原文明說】。實測程式已開源在 GitHub 的 HPMLL/NVIDIA-Hopper-Benchmark 倉庫【原文明說】。系列作延伸是學界常態，但讀者應該知道：部分表格與結論在 2024 年會議版就出現過，新貢獻集中在上述五個增量。

## 流程拆解

### 先看實驗台：三卡基本盤

論文表 2 先把三卡攤開：H800 PCIe 是 114 個 SM、80GB HBM2e、2039 GB/s 頻寬、50MB L2；A100 PCIe 是 108 個 SM、40GB HBM2e、1555 GB/s、40MB L2；RTX 4090 是 128 個 SM、24GB GDDR6X、1008 GB/s、72MB L2【原文明說】。注意 H800 是中國出口管制版 Hopper，不是 H100——PCIe 版功耗牆 350W，這個數字後面會咬回來。

### 第一單元：記憶體子系統——L2 分區是全文最細的解剖

傳統 P-chase 測出 L1 約 32～33 個時脈三卡一致、shared memory 約 29～31 個時脈【原文明說】；重點在 L2：A100 與 H800 都是雙分區設計，傳統方法只能看到兩段延遲（A100 約 202.8～408，H800 約 264.5～502），論文改用細粒度 P-chase 加 K-means 分群，拆出 near hit、far hit、near miss、far miss 四群——H800 分別是 258、414.1、555.5、743.7 個時脈【原文明說】。傳統方法在半滿 L2 量到的 264.5，恰好對上 near hit 的 258，互相咬合，這是方法可信的訊號【從原文可直接推出】。

吞吐方面，H800 的 L2 吞吐自述為 RTX 4090 的 2.6 倍、A100 的 2.2 倍【原文明說】；經執行驗算，表 5 的 FP32 欄位算出約 2.76 倍與 2.41 倍、FP32.v4 欄位算出約 2.31 倍與 1.96 倍，論文的 2.6／2.2 落在兩種量測口徑之間，屬於口徑選擇問題而非錯誤。全球記憶體頻寬達成率三卡分別為 92%、90%、91%【原文明說】，驗算（929.8/1008、1407.2/1555、1861.5/2039）得 92.2%、90.5%、91.3%，無勘誤。

### 第二單元：TMA——非同步搬運工，與 1.5 倍標題的落差

TMA 是 Hopper 的非同步拷貝引擎，Ampere 的非同步拷貝要每個 thread 自己算位址，TMA 只需一個 thread 建描述子、硬體接管定址與搬運【原文明說】。延遲測試顯示 TMA 比常規存取多約 170 個時脈的單元與同步開銷【原文明說】；吞吐上非張量、2D、3D 情境都可超過 1800GB/s，接近全球記憶體上限，但 1D 張量受 tensor map 的 shared memory box 上限卡住，論文直接建議一維搬運走非張量路徑【原文明說】。形狀選擇也有講究：同樣 16KB 搬運，x 維拉大有利，y、z 維拉大反而掉速【原文明說】。

應用層 GEMM 是關鍵一戰：`n大於7000` 的方阵，開 TMA 穩在約 600 TFLOPS、關 TMA 約 450 TFLOPS【原文明說】。經執行驗算，600/450 約為 1.33 倍——但摘要與結論寫的是加速 1.5 倍（五成）。這是全文唯一「標題跑在內文前面」的數字【從原文可直接推出】，可能來自特定尺寸點而非穩態值，讀者引用時應寫「在大矩阵下約快三成」，而不是「快五成」。

### 第三單元：Tensor Core——wgmma 滿血，mma 半血，FP8 貨真價實

演進表先定調：Hopper 的完整實力只能靠 warpgroup 層級的非同步 wgmma 發揮，舊的 mma 仍相容但吃不滿【原文明說】。指令層數字很直白：Hopper 上 mma 平均只能達到理論峰值的 62.9%，而 wgmma 在零初始化下各精度都超過 95%【原文明說】。但 wgmma 有個 H800 專屬陷阱：矩陣填隨機值時功耗頂到 350W 牆、降頻掉速，FP16 配 FP32 累加最明顯【原文明說】——這正是 H800 PCIe 版的功耗牆，不是 H100（700W 上下版本）的數字，跨卡引用會失真。

FP8 是成立最乾淨的一項：峰值 1513 對 FP16 的 756.5 恰為 2.0 倍，wgmma 實測 1448.4 對 729.3 為 1.99 倍【原文明說，比例經執行驗算】，摘要寫「近兩倍」是老實的。但兩處收斂要知道：一是稀疏 mma 在 H800 平均只比稠密快 1.42 倍，遠不如 RTX 4090 的近 2 倍，稀疏 tensor core 在 Hopper 沒吃滿【原文明說】；二是 LLM 推論實測（Llama 配 Transformer Engine、ShareGPT 輸入）屬 memory-bound，加上 TE 對 decode-only 模型支援不全、模組間仍以 FP16/FP32 傳遞，FP8 幾乎無感【原文明說】。訓練吃香、推論無感——精度紅利的適用邊界論文自己劃得很清楚。

### 第四單元：DSM——6.1 倍延遲是真的，但 broadcast 是反模式

DSM 讓同一 cluster 內 block 互訪對方的 shared memory。延遲數字：cluster 為 2 時跨 SM 存取 181 個時脈，比走 L2（264.5）少約三成、比走全球記憶體繞一圈（1110）快 6.13 倍，接近官方文件稱的 7 倍【原文明說，比例經執行驗算：1110/181 約 6.13】。但連本地 shared memory 走 DSM 介面都要 33 個時脈的額外開銷【原文明說】，能不用介面就不用。

Histogram 應用實測給出實務教訓：broadcast 式存取下 cluster 放大反而變慢，block 放大才能補 ILP；調對參數（block 512 配 cluster 2）可比不用 DSM 快三成以上【原文明說】。DSM 是 pattern-sensitive 的加速器，不是開了就快的開關【合理推斷】。

### 第五單元：DPX——16 位元的天堂，32 位元的平原

指令層：H800 在 relu 系與 16 位元整數操作最高約 13 倍加速，但 `__viaddmax_S32` 這類簡單操作三卡幾乎沒差（SASS 顯示 Hopper 用了 VIMNMX 新指令，效能就是沒拉開）【原文明說】。有意思的推斷是 DPX 加速單元應在 SM 層級：block 數未滿 SM 數時吞吐與 block 數成正比、剛超過 SM 整數倍時吞吐暴跌【原文明說】。

Smith-Waterman 實戰：S16 在 compute_90（硬體加速）下明顯優於 compute_80 與另兩卡，而 S32 開不開加速沒差【原文明說】；應用層加速 4.75 倍成立，但僅限 16 位元整數口徑。但全場最快的其實是 RTX 4090 跑 half 精度（4987.4 GCUPS），靠的是更高時脈與更多 SM——DPX 沒覆蓋浮點，消費級旗艦用老方法照樣贏【原文明說】。這是很好的口徑教材：4.75 倍是「Hopper S16 對自己人」的勝利，不是「Hopper 對全世界」的勝利。

## 風險與盲點

第一，測試卡是 H800 PCIe，不是 H100【原文明說】。H800 是對華出口管制版，互連被砍、功耗牆 350W——wgmma 隨機值掉速、FP8 峰值達成率等結論綁在這堵牆上，搬到 SXM 版 H100（功耗上限高得多）未必重現【合理推斷】。論文沒有 H100 對照組，這是全文最大的外部效度缺口。

第二，單一團隊、單一平台、無第三方複現。雖然 artifact 開源降低了重現門檻，但截至分析時未見獨立複現報告，證據等級給「中」【合理推斷】。以及前述的系列作背景：arXiv 管理員的重疊註記與作者自述的 IPDPS 2024 延伸，讀者遇到似曾相識的表格不意外，新料集中在 L2 分區、wgmma 能耗、DSM 全評估、應用層 DPX 與 TMA 非同步五處【原文明說】。

第三，幾個實作落差要寫進採購與調校清單：TMA 的 1.5 倍標題與 1.33 倍曲線落差（見上表）；FP8 在小 workload 下轉換開銷吃掉紅利、LLM 推論 memory-bound 下無感；稀疏加速在 Hopper 反而不如 Ada（1.42 倍對近 2 倍）；DPX 的 S32 操作幾無加速；DSM 的 broadcast 存取是反模式；Transformer Engine 對 decode-only 模型的支援尚不完整【以上皆原文明說】。通用核實禁語同樣適用：贏自家基線不等於泛化別家，单一團隊量測在有外部複現前都先當觀察哨。

利益揭露：作者群來自港科大廣州與哈工大深圳，通訊作者為 Qiang Wang 與 Xiaowen Chu，屬學術團隊，無課程、售書或返佣漏斗【原文明說】；經費與硬體來源未在可取得篇幅中揭露，讀卡時把 H800 的取得管道打個問號即可【合理推斷】。
