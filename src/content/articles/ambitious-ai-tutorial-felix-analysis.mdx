## 這篇文章真正解決的問題

**《Thomas Zhou X 貼文》解決傳播問題：** 把一篇英文長方法論翻成中文，讓中文圈讀者 8 分鐘吸收，並加了「2 分鐘精華版」跟進帖降低閱讀門檻。

**《Felix Rieseberg 原文》解決方法問題：** 「要有雄心」是 AI 圈的集結口號，但沒人告訴你第一步踩哪裡。作者把雄心拆成可執行的三個維度（高度／深度／廣度），每個維度給同一個 Acme 虛構公司的 QBR 貫穿案例，外加一個可直接複用的深度提示詞。這是**流程設計文件**，不是技術主張——所以核實的重點是譯文保真度與事實錨點，而不是數字。

## 流程拆解

### 模組一：譯文保真度抽查【原文明說】

抽查四處，譯文與《Felix Rieseberg 原文》逐段相符：

- 高度三階（基礎餵原始數據→進階提煉三個決策→高階重新設計評審機制並並行跑一季），齊全。
- 深度四問提示詞（頂尖專家會做什麼／最原始材料／具體方法工具／誰能證明結果正確），齊全。
- 廣度紅隊用法（不要扮演做空者，要執行做空者的調研動作），關鍵區分有翻出來。
- 尾聲典故（丹齊格遲到解出兩道難題、班尼斯特後 46 天紀錄被破、Linux「只是個業餘愛好」宣言）與題圖戈雅《飛行方式》，齊全。

### 模組三：三維框架可重用拆解

![雄心的四個維度整理](/article.ai/articles/ambitious-ai-tutorial-felix/figure-01-dimensions.svg)

<small class="figure-caption">自繪整理：高度／深度／廣度／速度四維與各自的操作入口，依據 Felix Rieseberg 原文。</small>

- **高度**：問「目標背後的目標」。適用信號作者自己給了——【原文明說】「你是否需要為手頭的事去開會討論」。純創意任務效果差，作者如實承認。
- **深度**：核心洞察是模型「換詞彙不換方法」——【從原文可直接推出】要求像專家就要指定專家的工具（資料庫、統計模型），而不是說「表現得像專家」。附帶的四問提示詞是全文最可直接拿走的構件。
- **廣度**：兩個技巧——動詞替換（出自《創新的藝術》，有署名）、組特遣隊找方法不做角色扮演。後者是對當下「AI 扮演專家」流行用法的直接糾偏。
- **共同前提**：模型需要可裝軟體的電腦環境＋資料存取（MCP 連接器等）。【合理推斷】這把大量輕量用戶擋在門外——框架的受眾其實是已有 Agent 基礎設施的人。

### 模組四：為什麼是自我效能感收尾

作者把心理學的自我效能感搬出來，論證「能力每幾週躍升一次的世界裡，瓶頸是想像力」。【合理推斷】這是全文真正的論點：方法論是術，敢把目標定高一級才是道。但注意——自我效能感研究說的是「具體且高難度目標勝過盡力而為」，不等於「目標越高越好」；深度一節裡「要求 200ms」這類離譜目標設定，在沒有外部裁判時正是獎勵駭客（reward hacking）的溫床，作者雖有「引入外部裁判」一節救場，兩者的張力並未真正解決。

## 風險與盲點

**1. 實現落差：軼事≠證據。** 全文案例（新行星、AI 音樂影片、零崩潰工作流）都是作者個人見聞，無基線、無對照、無失敗率。這恰恰違反了他自己「不要讓模型給自己打分」的精神——這篇教程也沒有外部裁判。拿去用可以，拿去當定論不行。

**2. 廠商視角偏差。** 作者是 Anthropic 工程主管，例子全是 Claude，雖聲明「建議不限模型」，但高度一節的持久工作流、MCP 前提，都是 Claude 產品線（Cowork、Claude Code）的舒適區。讀者自帶其他模型時要自行折算。

**3. 深度目標的副作用。** 「堅持說這完全可解、讓它繼續」在數學證明這類可驗證領域是美德，在商業決策這類開放領域可能把模型推向幻覺式自信。外部裁判一節是必需品，不是選配。

**4. 利益揭露。** 譯者 Thomas Zhou 自介為矽谷 Tech Lead＋天使投資人，每週一封「托馬斯的矽谷來信」——翻譯優質長文是其中文 newsletter 的標準獲客漏斗上層。翻譯品質經抽查是好的，但選文標準服務於傳播，不代表中立評測。

## 可操作步驟

1. 先拿走深度四問提示詞，下次開工前讓模型先回答那四問再重寫你的提示詞。
2. 高度練習：把你手頭最瑣碎的一個重複任務，連問三次「這件事之後接著要發生什麼」，直到問出一個可以取消會議的目標。
3. 廣度練習：把你的任務名詞換成動詞，找一個毫不相關領域的方法來做一次（例如用法務會計的方法查你的數據）。
4. 前置檢查：確認你的 Agent 有電腦環境＋資料存取，否則三維框架大部分招式發不出來。
