## 先說結論

這篇研究的答案不是「會寫 prompt 就夠了」。在這個實驗裡，**電腦科學成績與寫作能力都和 vibe-coding 表現呈正相關**；但在同時放進模型後，電腦科學能力的獨立解釋力大約是寫作能力的兩倍，兩者仍各自提供額外資訊。

更精確地說：這是一項相關研究，不是因果實驗。它支持「拆解問題、理解程式行為、把意圖寫清楚」都可能是 AI 協作開發的重要能力，但不能直接推出「多學 CS 就一定會變成更好的 vibe coder」。

## 研究到底測了什麼？

作者找來 100 名高等教育階段學生，讓他們完成四類測量：電腦科學成績（SCS1）、一般認知能力（ICAR16）、書面溝通能力，以及 vibe-coding 任務。參與者不能直接查看或編輯底層程式碼，而是觀察 GUI、用自然語言下指令、看結果，再迭代修正。

任務由 8 名具備 LLM／vibe coding 經驗的專家透過結構化共識流程設計。研究聚焦在 GUI 應用程式，包括複製既有 app、加入功能，以及一個缺乏上下文、需要更完整描述的任務。

## 主要結果：CS 的訊號比較強，但寫作仍然有用

研究者觀察到三個值得分開看的數字：

1. **CS 成績與 vibe coding：** Pearson's r = 0.386，p < .001。
2. **寫作能力與 vibe coding：** Pearson's r = 0.290，p = .003，屬於顯著但偏小的正相關。
3. **控制一般認知能力後：** CS 與 vibe coding 的部分相關仍顯著（r = 0.281，p = .005），但寫作與 vibe coding 的部分相關降為不顯著（r = 0.186，p = .066）。

<small class="figure-caption">圖 2｜原始論文第 11 頁結果表格截圖。注意：部分相關的顯著性與零階相關不同，不能混為一談。</small>

研究接著用階層式 OLS 比較兩種能力各自增加多少解釋力：先放入 CS 再加入寫作，寫作增加的 ΔR² 是 0.059；反過來先放入寫作再加入 CS，CS 增加的 ΔR² 是 0.125。換句話說，在這份樣本與任務裡，CS 提供的獨立變異大約是寫作的兩倍，但寫作並非沒有增量價值。

## 寫作能力真正可能影響的是 prompt 品質

作者的探索性分析提供一個較有意思的機制線索：人評 prompt 品質與 vibe-coding 表現的相關為 r = 0.479，p < .001；寫作能力與 prompt 品質的路徑為 0.35，p < .001。中介分析估計的間接效果為 0.152，95% bootstrap CI [0.061, 0.279]，約占總關聯的 52%。

但作者很明確地提醒，這仍然是橫斷面資料，**不能據此宣稱 prompt 品質造成了更好的 vibe-coding 表現**。比較保守的解讀是：寫作能力較強的人，可能更常產出清楚、組織較好的指令，而這種指令特徵又與更好的任務結果一起出現。

## 這篇研究沒有告訴我們什麼？

它沒有證明「寫作訓練會讓任何人變成更好的 AI 程式設計者」，也沒有證明「傳統程式設計已經不重要」。研究只測量 GUI 導向的、不能看底層程式碼的 vibe coding；參與者來自同一個都會區的多所大學，研究設計是橫斷面而且樣本只有 100 人。

另外，研究中的「寫作能力」不是單純文法正確，而是書面溝通、組織、推理與證據表達等綜合表現；這和一般人理解的 prompt engineering 課程並不完全相同。

## 對 AI 工具與教育的啟示

對工具設計者而言，這篇研究支持一個實用方向：不要只讓模型接受更長的 prompt，也可以幫助使用者拆解需求、補足遺漏條件、檢查矛盾，以及把修改前後的行為差異說清楚。

對學習者而言，值得練習的也許不是「神奇 prompt 句型」，而是三種可轉移能力：理解問題的結構、描述可觀察的行為、用例子和限制條件讓意圖變得可驗證。

## 我們的判讀

這篇論文最值得保留的訊息，是它把「vibe coding 只要會說話」這個流行敘事拆開了：語言很重要，但 CS 背景在這組資料中更能預測表現；同時，寫作仍然是獨立且有用的訊號。更穩健的未來工作，應該測試訓練是否能改變表現、不同年齡與專業背景是否得到相同結果，以及讓參與者可以查看程式碼後結論是否改變。
