<p><strong>GOOD NEWS 🧮 Tesla has figured out how to shrink AI's numbers without losing detail: give every token its own ruler and trim a bit the AI rarely uses 🔥</strong></p>
<p>The neural networks powering Tesla's cars and robots keep growing, and the ongoing challenge is fitting them onto onboard computers without needing a hardware upgrade every cycle. Two patent applications from the same four inventors tackle this challenge from complementary angles: a mixed-precision transformer (US 2026/0299881 A1) and a compact number format (US 2026/0299533 A1).</p>
<p>A common way to accelerate neural networks is to run their heavy math using 8-bit integers, which chips can crunch rapidly. But 8 bits offer only 256 distinct values, like a ruler with just 256 tick marks, forcing every number to round to the nearest tick. The traditional static approach sets the ruler's length in advance. That falls short when inputs shift: a scale calibrated for bright daylight compresses a dark night scene into just a handful of ticks, wiping out critical details.</p>
<p>The mixed-precision transformer solves this by resizing the ruler on the fly. Input data arrives as tokens (compact chunks of data). For each token, the system identifies its most extreme value and scales the ruler so that value lands on the very last tick mark. Every token gets its own tailored ruler, and no tick marks go to waste. Crucially, only the heavy matrix multiplications, where the bulk of the compute happens, drop down to 8 bits. Sensitive operations like normalization, softmax, and the running totals carried between layers stay in higher precision, preserving the numerical stability the network needs.</p>
<p>Many of those higher-precision operations rely on a format called BF15, introduced in the number-format patent. Computers store floating-point numbers much like scientific notation: an exponent defines the overall magnitude, while the remaining bits capture precision. The standard 16-bit format, BF16, allocates 8 bits to the exponent, providing a dynamic range spanning roughly 10⁻³⁸ to 10³⁸. But running inference on a trained model rarely demands that broad of a reach. Trimming a single exponent bit leaves a 15-bit format dubbed E7M7. It still covers a range of roughly 10⁻¹⁹ to 10¹⁹, but makes every value lighter to store and move across memory channels. Because it preserves all 7 of BF16's precision bits, trained BF16 models can run in E7M7 without any training-inference mismatch.</p>
<p>The number-format patent also outlines how to make E7M7 computationally cheap to handle in hardware. A value converts into a standard 32-bit float with a single shift, followed by two additions to restore its sign and translate the exponent back into standard form. From there, converting values into integers reuses the transformer's ruler trick: scale everything so the peak value lands on the final tick. Because every number gets multiplied by that scale factor anyway, an optimized hardware implementation folds the exponent fix directly into the scale itself, letting each value skip an addition entirely.</p>
<p>Together, the two innovations divide and conquer. One packs each token into 8-bit integers for heavy math without wasting dynamic range, while the other makes surrounding high-precision calculations smaller and faster to process. Both cut memory traffic, reduce power consumption, and speed up predictions, letting Tesla scale up its models while keeping existing chips in place.</p>

## 這兩件專利真正解決的問題

貼文解決的是敘事問題：車上與機器人上的模型越長越大，怎麼不換硬體就塞進去。專利解決的是兩個具體的技術問題，分開寫：

1. **靜態 INT8 量化的動態範圍浪費**（881 案）：8 位元只有 256 格，傳統做法事先定好尺的長度；輸入分佈一漂移（貼文的日光／夜景比喻），小值全擠在幾格裡，細節被抹掉。解法是動態量化層（dynamic quantization layers）：on the fly 按 token（也支援按通道、按區塊）各算各的 scale。
2. **推論時 BF16 指數範圍過剩**（533 案）：BF16 的 8 位指數撐出 10⁻³⁸～10³⁸，但前向傳遞維持精度用不了這麼大的動態範圍。解法是 E7M7：指數砍到 7 位（bias 從 127 改 63），尾數 7 位原樣保留，總長 15 位。

### 第三步：E7M7 的算法——剪指數、留尾數、bias 63

【專利［0036］明說】IEEE 浮點 bias 127 配 8 位指數；降到 7 位後 bias 變 63，仍可表示大到 10^19、小到 10^-19 的值；新格式 E7M7 與訓練期通用格式 bf16（E8M7）尾數位相同，故可免 train-test mismatch，直接拿 BF16 訓練好的模型跑推論。摘要裡「從指數部拿一位給尾數部」（reassign）的寫法是權利範圍的上位概括，E7M7 實施例是剪指數、尾數維持 7 位，兩者是概括與實施例的關係，不是矛盾（【合理推斷】）。

## 風險與盲點

- **申請案不是專利權，更不是量產（【仍未被支撐的主張】）**：A1 是公開號不是獲證號；審查可能限縮、也可能不准。專利通篇談的是 ego computing device／analytics server 的通用架構，沒有 HW4／AI4／AI5 的字樣，「keeping existing chips in place」是貼文的結論句，專利裡沒有。
- **「without losing detail」沒有數字**：兩件全文沒有任何精度、困惑度、速度、功耗實測，只有一句定性的「do not significantly degrade the model's performance」（881［0094］前後文）。沒有數據集口徑、沒有模擬 vs 實測對照，這句標題級承諾目前是零證據。
- **15 位元的對齊稅**：容量只省 1/16（6.25%），且 15 bits 非位元組對齊，存放要打包、讀寫要移位；若實作圖省事 pad 到 16 位，容量節省直接歸零，剩的只有 bias 63 帶來的指數運算簡化。貼文只談「lighter to store and move」，沒談打包代價。
- **per-token 定尺的離群值弱點**：`INT_MAX/max_abs` 把全 token 的動態範圍綁在單一極端值上，一個離群大值就能把同 token 其他值壓扁。專利給了 per-channel／per-block 選項，但沒談離群值偵測或裁剪，這是 INT8 量化文獻裡的經典坑。
- **指數範圍輕微不對稱**：bias 63 給出指數 −62～＋64，上寬下窄各一檔；專利用「substantially symmetric」帶過，工程上無礙，但讀到「對稱」字樣時知道它約等於對稱即可。
- **利益揭露**：@tslaming 自介為 Tesla／SpaceX／Neuralink 愛好者，屬同好解讀而非中立評測；但本次六項技術轉述經本站逐段核對大致忠實，立場未扭曲技術內容——取捨是：可引用其轉述的機制，結論句（已搞定、舊晶片夠用）要打折。

## 我們的判讀

《Tesla 雙專利》最值得帶走的不是 E7M7 這個格式，而是一個可遷移的判斷框架：**看到「量化專利」，先問「尺是誰定的、多久定一次」，再問「誰不用降精度」**。這兩件的答案很乾淨：尺是每個 token 用自己的最大值現定的（`INT_MAX/max_abs`），精度只降在矩陣乘法，norm、softmax、殘差流全部留在高精度；E7M7 則是把推論用不到的指數範圍還給儲存與頻寬。機制乾淨，但記住它停在申請案階段：沒有精度數字之前，「without losing detail」是願景不是結果。和站上另兩篇 Tesla 專利解讀（雙軸浮動卡扣談公差、Robovan 外觀談形狀資產）對照，Tesla 的專利佈局是三層各做各的：機構管組裝、外觀管識別、這兩件管推論成本；三者互不替代。
