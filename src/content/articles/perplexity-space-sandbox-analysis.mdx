## 一句話結論

《KC X 貼文》轉述的 Perplexity SPACE 開源與紅隊數字，幾乎全對——Apache 2.0、Firecracker、108 次零逃逸、11 次網路繞過、四個模型、Opus 主動放棄共享 IP 這條路，全部能在官方《Escaping SPACE: Part I》找到原文；要折價的有三處：「每天幾百萬個沙箱」比官方說法膨脹了一個口徑，E2B／Modal／Vercel 的修復狀態目前只有單一來源，以及官方自己寫在報告裡的警語——**沒觀察到逃逸，不等於證明隔離**。

## 這篇文章真正解決的問題

**《KC X 貼文》解決敘事問題：** 寫 agent harness 的人最痛的不是模型，是「給 agent 跑程式碼的環境」——隔離、狀態恢復、密鑰管理都要自己扛。SPACE 等於把 Perplexity 線上跑 Computer 的那套生產設施直接交出來，E2B 用戶改個 domain 就能切過去。

**《Perplexity 官方博客＋紅隊報告》解決技術問題：** 證明兩道邊界——VM 隔離（guest 逃不到 host）與網路約束（egress allowlist 關不關得住 agent），並且老實公佈自己在哪裡跌倒過。這是安全開源裡少見的寫法：先自曝 11 次被繞過，再說修好了。

## 流程拆解

### 模組一：開源本體核實【原文明說】

《perplexityai/SPACE GitHub 倉庫》首頁（抓取時 655 stars、44 forks）確認：

- 全名 Sandboxed Platform for Agentic Code Execution，授權 Apache-2.0，與貼文一致。
- 架構就是貼文說的那套：template 出初始環境，sandbox 是帶獨立 VM 與可寫檔案系統的實例；生命週期非同步（operation ID 輪詢），命令輸出走獨立 data-plane 連線。
- E2B 相容層真實存在（`docs/ecw.md`），用 E2B Python SDK 寫的 harness 對接可遷移。
- 部署門檻與貼文一字不差：apt 系 Linux x86_64＋KVM，需要 `/dev/kvm`、`/dev/net/tun`、loop device、btrfs；「these instructions do not run directly on macOS」。

## 風險與盲點

**1. 自家測自家，方法有天花板。** 報告出自 Perplashity 內部 Secure Intelligence Institute，不是第三方審計。官方自己把警語寫在正文：「一次成功的網路繞過不意味 VM 逃逸，沒觀察到逃逸也不證明隔離」。這句話應該貼在每一篇轉述的開頭。

**2. 第三方測試強度不對等。** 對 10 家友商用的是非 LLM 的 HTTP／HTTPS 探針，不是同等的 agentic 紅隊——只能證明「域名策略 vs IP 執法」的結構性裂縫普遍存在，不能證明「8 家都會被 frontier 模型玩弄」。KC 貼文沒有區分這層，讀者容易高估。

**3. 部分联网才是真實威脅模型。** 無網路 0／54、部分联网 11／54——agent 要裝套件就得放行 PyPI／鏡像，裂縫就從這裡來。自己配 egress allowlist 的團隊，真正的考題不是「關不關得住」，而是「放 PyPI 的同時擋不擋得住借 PyPI 的 IP 出去」。

**4. 實現落差：門檻與單節點。** 要 KVM＋Kubernetes，Mac 與無 `/dev/kvm` 的 VPS 直接出局；base snapshot 單節點限制意味著跨可用區的容災要另想辦法。評論區 @KoderNeverDie 點出的 execution generation 問題（恢復後舊連線會不會串到上一輪執行）是同一個家族的坑，驗收時值得實測。

**5. 利益揭露。** KC 為獨立開發者（寫遊戲與開源工具），無付費課程漏斗；利益相關方是 Perplexity 自己——開源＋自曝紅隊＋拉 CoreWeave／Akamai／Crusoe（《Semafor》10/15）做託管，本質是把 SPACE 推成 agent 沙箱的事實標準。敘事與商業是一體的。

## 可操作步驟

1. 想自部署：Linux＋KVM 備好，按倉庫 `docs/installation.md` 走 Kind 本地集群，先跑通 first-sandbox。
2. 已在用 E2B：讀 `docs/ecw.md`，評估相容層覆蓋的行為差異再切流量，別直接全切。
3. 自己配 allowlist：把測試矩陣抄過去——no-network 跑一遍、partial-network（放 PyPI）跑一遍，看 DNS 偽造與共享 IP 兩條路走不走得通；修復對照 nftables 源地址校驗＋SNI／Host 校驗。
